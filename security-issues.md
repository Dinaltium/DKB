# BusLink — Security Audit

**Scope:** Full repository — App Router routes, `proxy.ts` middleware (Next 16), server actions, Drizzle DB access, auth (`auth.ts`, NextAuth v5 JWT), crypto helpers, `next.config.ts`, the AAF11 connector, and build/seed scripts. Data flow traced across files (auth → session → server action → DB).
**References:** OWASP Top Ten 2021, CWE, CVSS v3.1.
**Method:** Static review + external evidence (Supabase advisor screenshot supplied by the owner confirming RLS-disabled tables).

> Note: several issues found earlier this session are already fixed in the current tree (quick-board UTR-capture auth, trip-tickets IDOR, cross-operator trip creation, UTR replay, guest-ticket-link ownership, seats-endpoint auth, PII-at-rest encryption). Those are **not** re-listed as open. See "Previously remediated" at the bottom.

## Additional confirmed findings (beyond top 10)

- **Business logic — free rides via honor-system (related to #3):** even with UTR replay blocked, no amount/authenticity check exists; a rider can ride without a genuine payment. Same files as #3.
- **Privacy — third-party IP geolocation:** `AppShell.tsx` sends the user's IP to `ipapi.co` on every load. Not an exploit, but discloses user IP to a third party; reconcile with the privacy policy.
- **Session cookies + JSON API:** state-changing API routes rely on the NextAuth cookie (SameSite=lax). CSRF risk is low because handlers require `application/json` bodies (not sendable by a simple cross-site form) and Next server actions carry origin checks — but confirm no state-changing handler accepts form-encoded bodies.

## Checked and found NOT vulnerable (evidence-based)

- **SQL injection:** all queries use Drizzle; the `db.execute(sql\`…\`)` blocks in `routes-admin.ts` and `${}` interpolations in `sql\`\`` templates are bound parameters, not string concatenation. No injection.
- **Command injection / RCE / unsafe deserialization / XXE:** no `child_process`/`exec`, `eval`, `vm`, or XML parsing on untrusted input found.
- **SSRF:** external `fetch` targets are fixed hosts (`router.project-osrm.org`, `ipapi.co`); host is not user-controlled.
- **File upload:** OCR runs client-side (Tesseract WASM); `app/api/ocr/route.ts` only runs regex over posted text — no file write/exec.
- **Hardcoded secrets:** none in source; `.env*` and `credentials.txt` are gitignored; no `NEXT_PUBLIC_` secret leakage.
