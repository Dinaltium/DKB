# Mobile build guide — BusLink Android

The Android app is a thin Capacitor 7 shell. It opens a WebView pointed at the deployed Vercel URL and forwards calls to native plugins (push, camera, geolocation) over the Capacitor bridge.

- One codebase. Every web deploy is live in the app on next launch.
- Status bar, splash screen, and adaptive icon match the BoldKit theme.
- The "Install BusLink" PWA banner hides automatically when the app detects it's running inside the native shell.

---

## Prerequisites (one-time)

| Tool | Why | Where |
|---|---|---|
| **Android Studio** (Hedgehog or later) | Builds the APK, manages emulators | https://developer.android.com/studio |
| **Java 17 JDK** | Required by the Android Gradle plugin | Bundled with Android Studio, or install separately |
| **Android SDK 35+** | Build target | Install via Android Studio's SDK Manager |

`pnpm install` already pulled in everything else (Capacitor CLI, plugins, etc).

A real Android phone in developer mode is the fastest way to test. Emulators work but boot slowly on Windows.

## File layout

```
capacitor.config.ts       # shell config (appId, server.url, plugins)
android/                  # Gradle project — committed
android/app/src/main/res/ # icons + splash, generated by pnpm cap:icons
android/.gradle/          # build cache — gitignored
android/app/build/        # APK outputs — gitignored
```

You do **not** edit anything under `android/` by hand for normal work. Capacitor regenerates assets on `pnpm cap:sync`.

## Daily loop

```bash
# 1. Whenever you change the web side, redeploy to Vercel (or run `pnpm dev`
#    on the LAN and point Capacitor at your IP — see "Local dev" below).
git push    # triggers Vercel deploy

# 2. Whenever you change capacitor.config.ts, add/remove a plugin, or
#    regenerate icons, sync into the Android project:
pnpm cap:sync

# 3. Open the Android project in Android Studio:
pnpm cap:open:android

# 4. Inside Android Studio:
#    Run → Run 'app'   (live on a connected device)
#    Build → Build Bundle(s) / APK(s) → Build APK(s)
```

That's the whole cycle. You almost never touch Java.

## Generating icons

The launcher icon and adaptive icon are rendered from `public/icon.svg` (any-purpose) and `public/icon-maskable.svg` (Android-adaptive safe-area). After editing either:

```bash
pnpm cap:icons   # render the 5 mipmap sizes + foreground + splash
pnpm cap:sync    # copy them into android/
```

You can edit the SVGs in any vector editor — they're just plain SVG.

## Local dev against your own laptop

By default the shell loads `https://dkb-chi.vercel.app/`. For native-feature work where you want to iterate on the web side, point it at your local server:

1. `pnpm dev` on your laptop.
2. Find your laptop's LAN IP (e.g. `192.168.1.34`).
3. Open `capacitor.config.ts` and change `server.url` to `http://192.168.1.34:3000`.
4. Add `cleartext: true` to the same `server` block (Android blocks plain HTTP by default).
5. `pnpm cap:sync && pnpm cap:open:android` → run on device.
6. **Revert both changes before committing.** Production must stay on HTTPS.

## Building an APK to hand to a tester

In Android Studio:

1. **Build → Build Bundle(s) / APK(s) → Build APK(s).**
2. When it finishes, a notification appears at the bottom of the screen — click **locate** to open the folder.
3. The file lives at `android/app/build/outputs/apk/debug/app-debug.apk` (~5–10 MB).
4. Rename it to something nice like `BusLink-v0.1.apk`.

To share with a tester:

- **WhatsApp / Telegram / Drive:** just send the file. Tester taps it, accepts "install from unknown sources", done.
- **Self-host:** drop it in `public/downloads/` on the Next.js app and link to `https://dkb-chi.vercel.app/downloads/BusLink-v0.1.apk` — but Vercel has a body-size limit, so this only works under ~50 MB. Fine for the debug build.

Debug APKs are signed with Android's default debug key, which is enough for sideloading but **will not be accepted by the Play Store**. For Play Store you need a release-signed APK or AAB — covered later when you're ready.

### Installing on a phone

On the receiving phone:

1. Open the APK file from wherever you put it (chat app, browser download, Google Drive).
2. Android shows "Install blocked — for your security, your phone is currently not allowed to install unknown apps from this source." Tap **Settings** → toggle "Allow from this source" → back → tap **Install**.
3. Open the app. The BoldKit splash shows for ~1 second, then the WebView fades in.

If the phone refuses to install at all, check:
- The APK was built for the right architecture (the default debug build is universal).
- The phone runs Android 7 (API 24) or newer — that's the Capacitor 7 minimum.
- The download wasn't corrupted (rebuild if size looks wrong).

## Native features wired up

| Feature | Plugin | Helper in `lib/native.ts` |
|---|---|---|
| Native status bar styling | `@capacitor/status-bar` | `setupStatusBar()` — runs on app boot |
| Splash screen | `@capacitor/splash-screen` | `hideSplash()` — runs on first paint |
| Push notifications (FCM) | `@capacitor/push-notifications` | `registerPush()` |
| Native camera (for ticket OCR) | `@capacitor/camera` | `captureTicketPhoto()` |
| Geolocation (live bus tracking) | `@capacitor/geolocation` | `getCurrentPosition()`, `watchPosition()` |
| Secure KV store (replaces `localStorage` on native) | `@capacitor/preferences` | `preferencesGet()`, `preferencesSet()` |

Every helper is **safe to call from any client component**. On the web they no-op or fall back to a browser API; on native they reach for the real plugin via dynamic `import()`. That means none of the native plugin code bloats the web bundle.

### Push notifications setup (when you're ready)

You'll need a Firebase project:

1. https://console.firebase.google.com/ → create project → add Android app with package name `com.dkbus.buslink`.
2. Download the generated `google-services.json` and drop it at `android/app/google-services.json`. (It's already in `.gitignore` — don't commit it.)
3. In Firebase project settings → Cloud Messaging, note the **Server key** (Legacy) or set up FCM HTTP v1 API credentials. Add as a Vercel env var like `FCM_SERVER_KEY`.
4. From the web app, call `registerPush()` on sign-in, POST the returned token to a new `/api/device-tokens` endpoint, store in a `device_tokens` table keyed by user.
5. To send a notification, POST to `https://fcm.googleapis.com/fcm/send` with the token. Easiest to wrap in a small server action so business logic stays in one place.

I'll wire this up end-to-end when you have the Firebase project ready.

### Background location (when you're ready)

The current setup uses Capacitor's foreground geolocation. True **background** location on Android requires:

1. An additional foreground service permission in `AndroidManifest.xml`.
2. A persistent notification while the service runs.
3. A Play Store privacy disclosure (Android 10+).

For your conductor / driver use case, the cleanest path is the `@capacitor-community/background-geolocation` plugin (not first-party but well-maintained). Worth waiting until you have Play Store approval, since the foreground-service rules are stricter than for sideloaded APKs.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `pnpm cap:sync` says "platform not added" | Run `npx cap add android` once. |
| `cap open android` opens Studio but build fails on JDK | Android Studio → File → Project Structure → SDK Location → set JDK to bundled JBR. |
| Gradle hangs on first build | First build downloads ~1 GB of dependencies. Let it run; subsequent builds are fast. |
| App opens but shows a blank white screen | The WebView can't reach `server.url`. Make sure the URL is accessible from the phone's network and HTTPS is valid. |
| Status bar shows light icons on a dark background | `pnpm cap:sync` after editing `capacitor.config.ts`. |
| App icon still says "C" or shows Capacitor logo | `pnpm cap:icons && pnpm cap:sync`. |
| `registerPush` returns null on first call | User declined the permission prompt; clear app data and retry. |

## Versioning

`android/app/build.gradle` carries `versionCode` (integer, must increment for every Play Store upload) and `versionName` (display string). Bump them for every release the user will see:

```gradle
android {
    defaultConfig {
        versionCode 2
        versionName "0.2.0"
    }
}
```

Wire this into a Vercel post-deploy job later if you want strict tracking.
